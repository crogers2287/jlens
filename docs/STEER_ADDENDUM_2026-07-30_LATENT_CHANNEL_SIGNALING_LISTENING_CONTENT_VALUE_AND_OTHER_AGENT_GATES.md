## Triggering primary evidence

Huixiang Zhang and Mahzabeen Emu, `Do Latent Channels Actually Communicate? A Causal Audit of Latent Multi-Agent LLM Communication`, arXiv `2607.26773v1`, submitted 2026-07-29, studies latent relay with Qwen3-4B and Qwen3-8B on GSM8K, ARC-Challenge, and MATH-500.

The paper separates five questions that end-task accuracy alone does not identify:

1. whether a sender property is decodable from the latent message;
2. whether message presence changes receiver predictions;
3. whether current-example message identity changes receiver predictions relative to an in-distribution other-example message;
4. whether current-example content adds objective task value; and
5. whether a separate sender adds value beyond a compute-matched message generated by the receiver itself.

Its four principal message conditions are:

- no message;
- an approximately length-matched message produced through the same interface for another example;
- a compute-matched self-generated message produced by the receiver; and
- the sender's message for the current evaluated example.

The audit intervenes after sender-side construction and before receiver-side injection while holding receiver context, weights, prompt template, decoding procedure, and downstream computation fixed. It treats embeddings, hidden-state sequences, and sender-produced KV rows as possible message carriers.

The reported results show why the decomposition matters. On GSM8K, the Qwen3-4B overall effect of the latent pathway was `-1.00` percentage point, decomposing into a `-6.17` point effect retained by an other-example message and a `+5.17` point current-example content effect. The directions reverse for Qwen3-8B. On MATH-500, the Qwen3-4B `+15.00` point overall effect decomposes into `+8.33` points retained by an other-example message and `+6.67` points attributable to current-example content. Prediction-distribution sensitivity and task-level utility also dissociate.

The paper-level result is not independently reproduced in jLens. No attributable immutable implementation of the new audit was located during this correction. The underlying public LatentMAS repository was inspected at `Gen-Verse/LatentMAS@9a9e4d331eb11430bd9e64754c6b252b06d73031`; that repository provides a latent-relay implementation, not by itself an admitted reproduction of every audit condition, result, artifact, or dependency.

## Binding interpretation

The new evidence establishes a protocol distinction not fully captured by ordinary probe, activation-patching, semantic-workspace, cache-lineage, or end-task gates alone:

> Information encoded in a latent message, receiver sensitivity to message presence, receiver sensitivity to message identity, objective value of current-example content, and incremental value supplied by a separate agent are different scientific objects.

The following identities may not be renamed into one another:

1. sender input and context;
2. sender checkpoint, state, and message-construction computation;
3. declared latent-message carrier;
4. current-example message;
5. other-example or other-population message;
6. receiver self-generated message;
7. no-message condition;
8. receiver injection boundary;
9. receiver prediction-distribution change;
10. sender-variable decodability from the message;
11. objective task value of current-example content;
12. objective value attributable to a separate sender;
13. component-level restoration effect;
14. final independently verified outcome;
15. communication, memory, latency, privacy, and systems cost; and
16. any policy or production decision.

A message may encode a variable that the receiver ignores. A receiver may react strongly to message presence while ignoring current-example content. Current-example content may help without requiring a separate sender. A separate sender may help even when current-example-versus-other-example task differences are small. Aggregate task gain cannot identify which mechanism produced it.

## Latent-message artifact identity gate

Every compatible study must freeze at minimum:

- exact sender and receiver repositories, immutable revisions, model classes, tokenizers, processors, templates, reasoning modes, and adaptation histories;
- whether sender and receiver share weights, embeddings, tokenizer, cache layout, runtime process, device, or random-number generator;
- agent topology, ordering, role prompts, number of senders, receiver identity, and aggregation rule;
- exact source example, source-group identifier, sender context, receiver context, and information available to each agent;
- carrier family: soft-token expectation, embedding sequence, hidden-state sequence, recurrent state, KV rows, complete KV cache, compressed cache, router state, expert output, or another prospectively named object;
- source layer, target layer, token or slot population, pre- or post-normalization stage, precision, quantization, packing, shape, length, masking, positional coordinates, and padding semantics;
- sender-side message-construction entry point, generation budget, stopping rule, sampling configuration, seed, and cache lineage;
- receiver-side adaptation, projection, realignment, fusion, concatenation, replacement, attention permissions, cache insertion, and residual-combine boundary;
- prefill, decode, prefix reuse, paging, migration, batching, concurrency, topology, and scheduler condition;
- parser, verifier, outcome definition, decoding procedure, invalid-output rule, and all complete costs; and
- train, calibration, validation, and sealed-test partitions for every probe, threshold, selector, or policy.

A tensor called `message`, `latent thought`, `workspace`, `memory`, `shared state`, or `KV relay` does not satisfy this identity gate without proving its exact producer, consumer, position, lineage, and executed dataflow.

Any change to the sender, receiver, message generator, carrier, interface, injection point, cache, topology, runtime, or verifier creates a new condition unless prospective equivalence is established.

## Sole-channel and boundary-isolation gate

A latent-channel causal claim requires proof that the declared message is the only inter-agent path changed by the intervention.

The study must freeze or eliminate at least:

- shared textual context and system prompts;
- sender answers or metadata copied into receiver prompts;
- example identifiers, ordering, lengths, padding patterns, and batch position;
- shared random seeds or correlated sampling state;
- process-global state, mutable singletons, adapters, and hooks;
- inherited prompt KV, receiver-generated KV, sender-generated KV, and stale cache rows;
- shared memory stores, retrieval results, tool results, files, environment state, and persistent agent memory;
- router, expert, scheduler, and cache-residency side channels;
- timing, tensor shape, allocation, communication volume, and error-path side channels; and
- preprocessing, parser, verifier, or selection differences downstream of injection.

The intervention must occur after sender-side construction and before the exact receiver consumer. Receiver context, model weights, prompt template, decoding, downstream computation, and verifier must remain fixed except for the declared message condition.

If another path changes, the result is a system-level intervention with multiple mediators, not an identified latent-message effect.

## Signaling, listening, identity, and task-value gate

Future latent-channel work must report these separately:

### Encoded sender information

A probe, mutual-information lower bound, or other decoder may establish finite-sample decodability of a frozen sender variable from the message. It does not establish receiver use, causal mediation, task value, semantic grounding, or a model-native workspace.

Required controls include source-group-disjoint splits, cross-fitting, label permutation, capacity-matched random features, message-length and norm controls, sender-output and answer-identity controls, and uncertainty appropriate to the estimator. Mutual-information lower bounds may not be reported as the channel's complete information content.

### Receiver sensitivity to message presence

Compare the current-example message against a prospectively defined no-message condition while holding every other receiver input and state fixed. The no-message implementation must specify whether it removes rows, masks them, replaces them with neutral state, changes positions, or changes cache shape. Each choice is a distinct intervention.

A prediction change establishes sensitivity to the presence condition. It does not establish sensitivity to current-example content or positive objective utility.

### Receiver sensitivity to message identity

Compare the current-example message against in-distribution messages generated through the same interface for other examples. Other-example assignment, source-group exclusions, approximate length matching, number of replacements, and averaging rule must be frozen before evaluation.

Prediction-distribution divergence establishes identity sensitivity at the measured boundary and continuation. It does not establish positive task value.

### Current-example content value

Compare independently verified task outcomes under current-example and other-example messages. This isolates the signed objective effect attributable to content generated for the evaluated example only under the sole-channel and matched-interface assumptions.

A positive effect does not establish that a separate agent is necessary. A negative effect does not establish that the message contains no decodable current-example information.

### Separate-agent value

Compare the sender's current-example message against a receiver self-generated message produced through the same interface under a matched and fully accounted computation budget.

This comparison must match or report message-generation steps, model calls, token or latent steps, cache construction, memory, latency, device work, and verifier exposure. A separate sender contributes incremental value only when the sender condition prospectively improves the independently verified outcome beyond this self-substitution control.

## Mandatory message-control ladder

Where technically compatible, future studies must include:

1. ordinary single-agent or no-communication execution;
2. declared no-message condition;
3. current-example sender message;
4. multiple other-example messages from the same benchmark and split;
5. other-population or other-benchmark messages;
6. receiver self-generated messages at matched complete cost;
7. sender self-substitution when sender and receiver roles differ;
8. source-permuted messages preserving message marginals;
9. length-, norm-, position-, carrier-, and cache-shape-matched controls;
10. zero, mean, random, shuffled, and scrambled messages as diagnostics only;
11. current-message restoration from an other-example baseline;
12. wrong-layer, wrong-position, wrong-component, and neighboring-subspace restoration controls;
13. ordinary text-message communication at matched task and systems cost; and
14. no-intervention full-compute fallback.

Synthetic noise, zeros, or arbitrary scrambling may reveal receiver instability but are not primary evidence for natural-message content because they can create off-distribution states. In-distribution model-generated replacements are primary where feasible.

## Matched-compute and self-substitution gate

`More agents`, `latent collaboration`, and `shared workspace` systems often add computation independently of message content. Every claimed communication benefit must report:

- sender and receiver forward passes;
- latent generation steps;
- text generation steps;
- cache construction and transfer;
- adapter or projection work;
- expert dispatch and communication;
- memory traffic and storage;
- scheduler and batching overhead;
- parser and verifier calls;
- retries and invalid-output handling; and
- expected, median, tail, and worst-case latency and cost.

A receiver-generated control must use the same carrier and injection interface and a prospectively matched resource budget. If exact matching is impossible, the unmatched dimensions and resulting identification limit must be explicit.

A multi-agent gain over a cheaper single-agent baseline does not establish efficient communication. A gain over a compute-matched receiver self-message does not establish semantic transparency. A lower token count does not establish lower total compute, memory, bandwidth, or latency.

## Prediction-distribution and objective-outcome gate

First-token divergence, teacher-forced continuation divergence, free-running continuation divergence, parser-valid answer change, exact-match accuracy, verifier-approved task outcome, and downstream agent success are different endpoints.

Future work must freeze:

- the compared prediction distribution and token boundary;
- divergence metric and numerical floor;
- whether continuation is teacher-forced or free-running;
- answer parser and invalid-output policy;
- objective verifier and its revision;
- paired outcome definition;
- treatment of stochastic decode seeds; and
- multiple-comparison and equivalence procedures.

Large prediction sensitivity does not imply positive task value. Small first-token sensitivity does not imply absence of later causal effect. Outputs without a valid parsed answer remain in the objective analysis under the preregistered failure score rather than being silently removed.

## Inference, equivalence, and hard-check gate

Compatible studies must use paired example-level inference and report uncertainty for every signed effect. Multiple other-example replacements must be averaged within the evaluated example before population aggregation unless another rule was preregistered.

Practical-negligibility claims require a prospectively declared equivalence margin and valid equivalence test. A confidence interval crossing zero is inconclusive; it does not establish absence, equivalence, or negligible effect.

At minimum, the implementation must pass deterministic hard checks showing that:

- repeated identical receiver executions define the numerical reference floor;
- masking or eliminating the declared message removes message-identity effects to that floor when the design predicts it should;
- substituting the current message for itself produces zero current-versus-replacement effect;
- current-message restoration recovers the declared complete-message endpoint within tolerance;
- a deliberately broken, stale, wrong-example, or no-op replacement is detected;
- receiver-generated cache rows are not overwritten when only sender rows are replaced;
- hooks and wrappers reach the actual executed consumer; and
- public tables derive from the admitted path and immutable artifacts.

## Component restoration and mediation gate

A component-level claim requires an executed intervention at the exact pre-consumption boundary. Starting from an admitted other-example message, restore prospectively defined current-example components while leaving all other message and receiver state fixed.

Every restoration study must report:

- component definition and selection rule;
- source and destination lineage;
- insertion boundary and downstream consumers;
- complete versus partial restoration;
- output-distribution and objective-outcome recovery;
- random, mean, wrong-example, wrong-layer, wrong-position, neighboring-component, and norm-matched controls;
- nonadditivity and interaction among restored components;
- off-distribution and receiver-instability diagnostics; and
- full restoration, no-op, and identity hard checks.

A component that restores prediction divergence is not automatically necessary, sufficient, semantic, or beneficial. A normalized restoration score is undefined or unstable when its denominator is near the numerical floor and may not be used there.

## Semantic-workspace claim boundary

No latent carrier may be called a `semantic workspace`, `shared reasoning medium`, `agent language`, `belief state`, `metacognitive channel`, or `error state` from any one of the following alone:

- high dimensionality;
- linear or nonlinear decodability;
- message-presence sensitivity;
- message-identity sensitivity;
- aggregate task gain;
- token or latency reduction;
- sender-answer correctness decodability;
- component restoration;
- vocabulary-indexed coordinates;
- compression robustness; or
- router or expert specialization.

A workspace claim requires source-group-disjoint replication across tasks, populations, seeds, checkpoints, carrier families, and runtimes; explicit sender-to-receiver causal use; current-example content value; comparison with compute-matched self-generated state; matched text, random-subspace, raw-state, cache-only, and extra-compute controls; component and interaction tests; and independently verified outcomes.

Even those results establish an engineered communication interface under the tested conditions, not necessarily the model's unique natural reasoning medium.

## Privacy and sealed-data boundary

Latent messages can carry prompts, private records, credentials, tool observations, user identity, system instructions, or memorized data even when no text is decoded. Public publication of aggregate task metrics does not authorize publication of the carrier.

Every future latent-channel study must separately account for:

- data available to the sender;
- data transmitted in the declared message;
- data decodable by a receiver or auxiliary probe;
- data retained in caches, checkpoints, traces, logs, and crash artifacts;
- cross-tenant or cross-example reuse;
- provider, device, and network exposure;
- deletion and invalidation behavior; and
- privacy loss caused by diagnostic probes or message replacements.

Other-example and self-generated controls remain private or sealed when derived from private tasks. No per-example message, probe score, reconstruction, route, cache row, or verifier outcome may be committed to this public repository.

## Router, expert, and MoE boundary

A latent message entering an MoE receiver may change router logits, top-k identities, mixture weights, expert capacity, communication, cache state, and later hidden states. These are downstream consequences of the message condition, not interchangeable evidence of semantic communication.

Future MoE studies must freeze and report separately:

1. message carrier and injection boundary;
2. pre-router receiver state;
3. raw router logits and probabilities;
4. routing transforms, top-k identities, ordering, and weights;
5. physical expert execution and communication;
6. expert outputs and residual combination;
7. later attention, recurrent, cache, and route state;
8. prediction-distribution effect;
9. independently verified task effect; and
10. complete systems cost.

Router changes can mediate a message effect without proving that experts correspond to semantic roles. Route stability can coexist with content-based communication, and route variation can occur without positive task value.

Frozen-route, recomputed-route, route-swapped, matched-marginal, and random-route controls are separate interventions and remain subject to every existing router, assignment, derivative, and production gate.

## Jacobian boundary

The following derivatives are different scientific objects:

- sender-output Jacobian with respect to sender input;
- message-construction Jacobian;
- receiver-state Jacobian with respect to the injected message;
- receiver-logit Jacobian with respect to the message;
- end-to-end sender-input to receiver-output Jacobian;
- fixed-route receiver Jacobian;
- controller- or router-included Jacobian; and
- finite changes that cross discrete routing, cache, parser, or stopping boundaries.

A large local Jacobian norm establishes local sensitivity at the named point. It does not establish natural-message use, current-example content value, separate-agent value, global causal effect, objective correctness, or safe control.

Any Jacobian-based latent-channel study must first pass exact forward, VJP, JVP, and finite-difference parity at the declared sender, message, injection, cache, and receiver boundaries. It must then demonstrate sealed incremental value beyond message norms, lengths, logits, entropy, ordinary probes, raw hidden-state features, receiver-state features, transparent communication contrasts, and external verifiers.

Jacobian features may be used for passive analysis only until a separate intervention protocol establishes counterfactual utility, regressions, tail risk, rollback, and full-compute fallback.

## Established by this correction

- Encoded sender information, receiver use, current-example content value, and separate-agent value are different claims.
- Message-presence sensitivity and message-identity sensitivity are different claims.
- Aggregate task gain can conceal opposing content-dependent and content-independent effects.
- Prediction-distribution sensitivity and objective task utility are different endpoints.
- Current-example content can add value without proving that a separate sender is necessary.
- A separate sender can add value without proving a generic semantic workspace.
- In-distribution other-example replacement and compute-matched receiver self-substitution are required controls for compatible claims.
- The declared message must be the sole changed inter-agent path for a message-level causal interpretation.
- Latent carriers remain private or sealed even when they are not decoded into text.
- Router and expert changes downstream of a message are not semantic labels.
- Local Jacobian sensitivity is not communication value or objective correctness.
- Existing privacy, sealed-data, verifier, provenance, derivative, intervention, and production gates remain intact.
- Q35Q remains blocked.
